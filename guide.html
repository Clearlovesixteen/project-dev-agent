产品概览

Project Dev Agent

让 Codex 带着项目依据完成开发，并把有价值的纠正留给下一次任务。

v0.6.2 · Codex 原生插件2026.10.15约 3 分钟阅读

接入 Codex 的项目开发工具包：检索项目惯例和业务约束，记录关联改动清单，把纠正经验保存为可审查的知识。入口是 Codex 中的 project-dev Skill，状态和检索由本地 STDIO MCP 服务提供。

v0.4 增加全项目结构索引和按需业务理解：首次接入扫描模块、入口、公共能力和直接导入关系；开发具体需求时保存带源码依据的模块候选，来源变化后提示复核。历史习惯发现继续保留：首次接入项目时分析本机可归属该项目的 Codex 历史，提取有原话依据的偏好与业务纠正，并接入日常检索。保留个人安装、多仓库隔离、任务恢复与命令行审查。核心工具不依赖某个业务项目、模型 API Key、数据库或向量服务。

工具 用途
project_prepare 检查当前仓库，按需准备 Git 忽略的本机记录，保留业务改动
knowledge_search 按模块、路径和关键词检索规则，返回来源、版本和复核提示
task_open 从干净 Git 基线建立任务和验收项
task_update 保存关联清单、核对证据、纠正理由和已使用的知识版本
task_check 恢复活动任务，比对清单与实际变化，报告待核对项、清单外文件和基线异常
experience_propose 从具体纠正生成候选草稿，保留适用范围和待确认点
history_scan归属项目历史、提取可见文本、复用未变化批次，并报告覆盖范围
history_next读取下一批待分析对话及来源，恢复中断的进度
history_record校验用户原话，保存候选与分析进度，生成可翻页的 HTML 报告
project_scan建立或刷新全仓结构索引，返回覆盖范围及 HTML 报告
project_context查找参考实现、直接引用与使用方，核对相关文件和模块理解的新鲜度
project_model_record保存有源码原文、哈希和修订号的模块理解候选

默认使用简体中文说明任务、业务模型和习惯候选；工具名、字段、源码及历史原话保持原样。已有记录不批量改写，重新生成的报告使用中文分类。

快速开始 · 原生插件

v0.6 通过公开的 GitHub 插件源分发预构建插件。需要 Node.js 18.19.0+、Git 和 Codex。使用 HTTPS 匿名下载，无需协作者邀请、GitHub 账号或 SSH 密钥，同事无需源码构建。

bash
codex plugin marketplace add https://github.com/Clearlovesixteen/project-dev-agent.git --ref main
codex plugin add project-dev-agent@project-dev-team

重启 Codex 并在业务仓库新建对话，直接使用 $project-dev 描述需求，首次运行会自动检测并初始化当前仓库。需要调整工作范围时才使用“项目设置” $project-dev-setup；更新使用 $project-dev-update 更新到最新版。个人配置和项目记录跨版本保留。详细步骤见安装与更新。

从源码开发或运行独立示例：

bash
npm ci --ignore-scripts
npm run check
node dist/src/cli.js doctor
node dist/src/cli.js sample create --destination /tmp/account-agent-demo

样例会创建独立 Git 仓库，目标目录须尚不存在。doctor 只验证运行环境，不验证桌面当前会话。示例只展示机制，不能作为真实业务效果证据。

调用 Skill 后，它会建立或刷新项目结构索引，恢复或完成当前仓库的历史分析，再围绕需求核对相关源码和候选。无需粘贴长提示词，也无需另配模型；分析使用当前 Codex 会话，会消耗会话额度。详见 历史习惯发现。

首次接入的动作、结构索引边界和按需业务建模见 项目结构与业务理解。

项目数据

text
.project-dev/
  project.yaml         # 知识目录、模块范围和排除路径
  knowledge/*.md       # Git 管理的共享知识
  local/               # Git 忽略的本机数据
    tasks/*.json       # 修订号、清单、证据、纠正记录
    understanding/     # 结构索引、模块理解修订与 HTML 报告
    history/           # 私人历史文本、分析进度与 HTML 报告
    proposals/*.md     # 尚未确认的经验草稿

知识有 candidate/confirmed/needs_review/disabled 状态。默认检索返回来源仍有效的已确认规则。代码和文档保存内容哈希，文件变化或缺失会提示复核；经验来源保留人的审查记录。规则适用条件仍需 Codex 或开发者结合当前任务判断。

模板见 templates/knowledge.md，经验审查见 经验审查说明。第一批知识可从已有代码惯例、业务文档和同事已确认的经验中整理；工具不会自动归纳并确认整库业务规则。

验证与边界

bash
npm run typecheck
npm test
npm run test:integration

测试覆盖关联待核对项、陈旧修订号、冲突基线、任务恢复、知识范围和来源变化、纠正复用、初始化幂等及真实 STDIO 客户端调用。实测状态见 验证报告。

同一工作树只允许一个活动任务。任务开始前须干净且已有提交；任务中的正常提交仍与原基线比较。关闭任务要求清单与验收有证据；中止保留历史。工具核对结构化记录与文件覆盖，无法独立证明业务正确，也无法发现所有未登记的业务关联。核对后若再次修改代码，需要重新审查相关证据。

检索使用范围筛选与关键词排序，尚未提供 AST 影响分析、向量语义搜索或跨仓库影响分析（workspace 模式只提供隔离路由）。审查人字段记录来源，不提供身份认证。真实团队的纠偏、漏改和额外负担，需要试用后才能得出结论。
