从经验到共享规则

  1. 先在具体任务中记录纠正内容、原因和来源。
  2. 将适合复用的经验保存为候选草稿，明确适用范围与待确认问题。
  3. 经过明确审查后，才可将规则标记为 confirmed 并通过团队的 Git 流程共享。
来源代码或文档变化后，需要重新核对规则。工具不会自动确认业务规则，也不会用文件已修改代替业务验收。
