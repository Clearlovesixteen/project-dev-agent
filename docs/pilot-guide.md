# 第一轮试用

通用工具和合成样例可以先行验证，真实项目用于判断是否帮助同事，在这一步接入。

选择一类经常需要纠正实现思路的需求，整理少量已确认惯例、业务约束和关联经验。保留来源、适用范围与审查人。先选可独立核对的小任务，避免把大重构混入对比。

对照三组：原有 Codex、提供相同知识的 Skill、Skill 加 MCP。固定起始提交、需求、知识版本、模型和关键配置，每轮使用独立工作树。只有 MCP 组增加结构化状态工具，避免把额外知识优势误算成状态管理优势。

从 8–12 个案例回放开始，记录成功、失败和中止，再让少量同事日常试用。熟悉项目的人核对实现，观察纠偏次数、关联漏改、补改时间、错误提醒和操作负担。样例通过只能证明流程运行，不能推出团队效率提升比例。

每个案例使用 `evals/case-template.md` 留原始记录。以完整分母报告结果，列出仍会遗漏的业务关联；得到基线后再确定绩效中的提升目标。
