首次会做什么

  1. 识别当前 Git 仓库，准备 Git 忽略的本地状态目录。
  2. 枚举 Git 已跟踪和未忽略的新增文件，筛选可支持的源码、配置和文档。
  3. 记录文件版本，识别目录或配置中的模块边界、路由入口和页面、公共能力、接口层及测试线索。
  4. 提取 JavaScript/TypeScript 等文件中的字面量导入，以及 package.json 的依赖声明和脚本名称；不执行脚本。
  5. 继续历史对话分析，将用户纠正与当前实现对照核实。
  6. 生成 HTML 项目报告。正式开发时检索相关入口和使用方，再建立改动清单。

入口仍是一句 $project-dev 帮我实现这个需求：……。只做接入可说 $project-dev 接入当前项目，生成项目理解报告。结构扫描可以在有未提交业务改动时运行；开正式开发任务仍遵循原有干净基线要求。

扫描得到哪些内容

结果用途需要核实的边界
模块与文件角色找到页面、公共组件、接口和测试入口目录归类是线索，不能自动决定业务边界
直接导入和使用方提示可能需要一起检查的文件字面量解析不是完整 AST，无法覆盖动态调用和所有业务关系
依赖声明、脚本名称定位组件库与验证入口声明版本不证明实际安装能力；不自动运行任何命令
文件内容哈希检测已读取依据是否变化内容相同不证明业务规则正确，变化也不一定意味着语义失效

全仓枚举受 Git 可见范围和格式支持限制：排除 node_modules、dist、build、coverage、vendor、缓存、本地 Agent 状态、常见凭据文件及项目自定义排除路径。嵌套仓库和符号链接不跟随；无法读取时报告不完整。当前上限为 10,000 个可索引文件、约 80 MB 总读取预算、单文件 512 KB。超限会明确显示未覆盖。

导入提取主要面向 JS、TS、Vue、Svelte，支持常见相对路径，以及根 tsconfig/jsconfig 直接声明的别名；不执行配置、不追踪 extends。其他支持的语言可以建立文件与目录索引，暂未提供它们的语言级依赖分析。

业务理解如何逐步形成

处理一个具体需求时，Codex 阅读相关代码、现有文档和历史纠正，再记录术语、流程、职责、关联文件和待确认问题。例如只核实仓风险说明，就保存“配置值怎样取、页面怎样展示、哪些后端规则尚未核实”，不会把它包装成完整补货模型。

每条模块记录需要真实源码原文、行号、当前索引哈希，并覆盖所有引用文件。服务验证原文和版本匹配；它无法自动证明模型推断正确。所有记录保持候选状态，不能代替当前用户要求，也不自动成为团队规则。

更新模型必须带最新修订号，旧修订文件保留。查询会检查所有已登记关联文件；变化、缺失或无法读取会使模型进入 needs_review。必须重新阅读并修正理解，再保存新修订。不能仅重新计算哈希就宣布规则有效。

技术调用与数据

project_scan 建立结构快照，project_context 查询参考实现、直接引用和模块理解，project_model_record 保存源码支持的候选。workspace 模式每次显式传当前 Git 根目录。既有 knowledge_search 也返回 understanding 线索，与确认知识分开。

.project-dev/local/understanding/
  manifest.json       项目身份、扫描范围和文件块索引
  chunks/*.json       内容寻址的结构记录
  models.json         当前模型修订指针
  models/*.json       保留历史修订的候选模型
  report.html         HTML 报告入口
  report-*.html       模型、模块与文件的后续页面

重复扫描仍读取文件计算版本，复用未变化文件的提取结果，再重新解析引用目标。不会重复调用模型理解全部源码。新会话开始时刷新结构；具体查询只核对选中的文件和返回的模型来源，新文件需要扫描后才能进入索引。

project-dev-agent project scan --project /absolute/repository
project-dev-agent project context --project /absolute/repository --path src/pages/example
project-dev-agent model record --project /absolute/repository --file /absolute/model.json

单个生成文件上限 64 KiB；查询和 HTML 按数量与字节数限流，结果会标记截取，报告可翻页查看全部索引条目。极长记录的完整内容保留在 JSON 中。源码与历史片段均视为待分析数据，不执行其中的指令。

验证与剩余边界

测试覆盖扫描与引用、别名变化、增量复用、原话引用、模型修订、源码失效、排除路径、链接与嵌套仓库、HTML 分页、实际 MCP 重启恢复及旧 Skill 升级。实测见 验证记录。

暂不提供完整 AST 影响分析、运行时调用图、全业务自动建模、跨仓库推理或向量检索。减少纠偏和漏改的实际收益仍需要真实需求验证。结构扫描和已有规则始终不能替代任务中的代码检查与验收。
