# 数据契约 v1

这些类型是产品内部契约，不是 Codex 的内置数据结构。实现位于 `src/domain/`，使用严格 Zod 校验并导出 TypeScript 类型。

**任务与影响清单**

任务保存工作树身份、起始版本、需求、验收条件、知识版本、清单和验证记录。更新时比较 `revision`，成功后加一，陈旧版本不覆盖新记录。本地状态使用原子写入与进程锁，同一工作树只允许一个活动任务。

清单的 `target_path` 是项目内相对文件路径，便于后续与 diff 对应。一项记录处理一个位置；同一业务要求可以对应多个位置。相比设计草案中的 `target_path_or_component`，首版明确为文件路径，组件级聚合可后续增加。

| 状态 | 必须具备 | 含义 |
| --- | --- | --- |
| pending | 要求、关联原因、来源 | 尚未完成核对 |
| checked | 核对者、至少一条证据 | 已记录检查结果；不是系统自动证明正确 |
| skipped | 核对者、无需处理的理由 | 明确决定本次无需处理 |

验收条件使用独立的 `pending/checked` 状态，并要求核对者和证据；不能因为清单中的文件被修改就自动通过验收。

任务阶段为 `active/closed/aborted`。关闭要求非空清单全部核对、验收条件全部核对，已有验证记录均通过；缺少记录的实际验证并不能由格式校验发现。中止必须注明理由，保留未完成项。结束记录只读，关闭还会检查基线与清单外变更。

证据分为 `code/test/manual`，包含引用和检查摘要。校验引用格式不会自动读取代码或执行命令，也不能保证记录内容真实。

**项目知识**

知识类型：`code_convention/business_rule/change_relation`。状态：`candidate/confirmed/needs_review/disabled`。所有知识保留来源和范围；已确认、需复核状态需要确认人和复核时间。停用记录保留历史依据。

范围可使用模块、相对路径或适用条件，至少有一项。路径允许仓库内 glob，但拒绝绝对路径、上级目录、反斜线和空段。来源指向代码、文档或经验；本地读取拒绝符号链接和非普通文件，并限制大小。

知识包含 `schema_version: 1`、标题、来源和 `review_questions`。确认前必须解决待审问题。代码与文档来源可带 `sha256`；缺失快照或文件变化时，已确认规则在检索中转为需复核提示。内容版本采用知识文件 SHA-256，任务记录已采用的 ID/版本。

`experience_propose` 从已有任务纠正生成候选 Markdown，只写本地草稿。明确的 `knowledge review` 命令保存确认人、时间和来源快照，写入共享知识目录；MCP 不暴露确认能力，审查人字段不是身份认证。

**工具结果**

`outcome` 为 `ok/incomplete/error`；后两种必须提供诊断说明。一次调用成功与开发需求完成分别表达，避免把记录写入成功当作改动已完成。

记录均拒绝未知字段；任务各集合 ID 不得重复；日期必须使用带时区的 ISO 时间。由源码归纳出的候选知识不会自动获得确认状态。
