开发者诊断怎样使用

目的：帮助插件维护者按真实执行结果定位问题、修复和复测。普通使用者继续开发，不增加打分、导出周报或管理流程。

本次提供本地诊断、Workers + D1 收集端和维护者报告。在线服务由维护者在自己的 Cloudflare 账户部署。0.13 新安装默认配置公开接收端，安装说明中明确告知采集范围和关闭方式；已有关闭或自定义配置保留。插件只内置可公开的接收标识，不包含私有写入或读取凭证。控制面发布成功后，还需从实际使用环境验证接收链路；钩子与 MCP 的执行失败均独立降级。

数据怎样流转

本插件钩子 / MCP / 验证器→严格白名单 · HMAC 去标识→本地 JSONL→公开默认策略 / 用户配置 · 可关闭→Worker 公开 /public/events 或私有 /events→维护者 D1 私有数据库

每批最多 50 条，单事件最多 4096 字节。只有接收端确认持久提交后才推进游标；确认丢失可安全重试，同一安装和事件 ID 去重。关闭 / 重开 / 更换接收端生成新周期，旧周期不补传。HTTPS 之外只允许本机回环 HTTP 用于测试。响应大小、发送时间、重试频率均有上限。

为什么不直接存 GitHub

GitHub Pages 是静态托管，不能充当接收 API。通过仓库写入或 dispatch 需要写权限凭证，不应把你的 GitHub Token 放进同事插件。当前方案由 GitHub 管理服务代码，Workers 运行接收 API，D1 保存元数据；公开代码中没有诊断数据或读取凭证。

维护者部署步骤

  1. 在维护者自己的 Cloudflare 账户创建 D1 数据库，保存数据库 ID。无需私人服务器或自购域名，但需要该服务账户及自己的资源额度。
  2. 在仓库根安装维护依赖后构建：node tools/diagnostics-collector/build.mjs。同事不需要安装 Wrangler。
  3. 复制 wrangler.example.toml 为该目录下的 wrangler.toml，填入自己的数据库 ID；该本地配置已被 Git 忽略。
  4. 使用已登录的维护者 Wrangler 初始化数据库并部署。本次实测授权范围为 account:read、user:read、workers:write、workers_scripts:write 和 d1:write；独立的 Workers Scripts Write 负责脚本、子域名与触发器管理，不能只选 Workers Write。首次发布前，先在 Cloudflare 的 Workers & Pages 页面初始化账户的 workers.dev 子域名。令牌通过交互式 secret 输入，不放进命令参数、聊天、提交或日志。
npx wrangler@4.155.0 login --device --scopes account:read user:read workers:write workers_scripts:write d1:write
cd tools/diagnostics-collector
npx wrangler@4.155.0 d1 migrations apply project-dev-diagnostics --remote
npx wrangler@4.155.0 secret put WRITE_TOKEN
npx wrangler@4.155.0 deploy

本次维护端实测 Wrangler 4.155.0，运行它需要 Node 22 或以上；同事仍沿用插件原有的 Node 18.19.0 最低要求，不需要安装 Wrangler。按工具提示完成登录，并在 Cloudflare 页面核对授权。WRITE_TOKEN 至少 16 位随机字母、数字、下划线或短横线；它只用于该接收 API，不授予 GitHub 或数据库读取权限。收集端仅提供 POST /public/events 和私有 POST /events，其他路径均返回 404；公开标识不能读取数据、不能调用私有入口，也不认证成员身份。公开入口的来源、安装和总量限流按 Cloudflare 位置近似生效，不等同严格费用上限。生产服务应保持账户访问控制和资源额度监控。

用 GitHub 更新收集端

可在 Workers 的 Builds 中连接本 GitHub 仓库。仓库根作为构建目录，构建环境设置 PROJECT_DEV_DIAGNOSTICS_DB_ID 为自己的数据库 ID，选填 PROJECT_DEV_DIAGNOSTICS_WORKER（需与平台 Worker 名称一致）。构建命令为 npm ci --ignore-scripts && node tools/diagnostics-collector/build.mjs && node tools/diagnostics-collector/configure.mjs；部署命令为 npx --yes wrangler@4.155.0 deploy --config tools/diagnostics-collector/wrangler.toml。生成配置不会提交 GitHub，WRITE_TOKEN 放 Worker 运行 Secret。首次初始化与后续数据库升级均使用 migrations apply；先迁移再部署，旧表与历史记录保留，新增 ingest_source 标记 public/private。若采用其他部署系统，保留相同的构建、初始化与密钥隔离原则。本地 Wrangler 发布不会自动建立 GitHub 联动；需要维护者另行连接自己的仓库。

安装者怎样使用

  1. 安装或更新插件后，按 Codex 要求审查信任原生钩子。新安装在 MCP 或已信任钩子首次运行时自动配置公开接收端，日常无需填写参数、登录收集服务、打分或写报告。
  2. 新建运行配置才应用默认策略；旧版本已保存的关闭、本地停用或自定义接收配置保持不变。旧用户主动开启默认接收端可说“$project-dev-setup 开启默认诊断上报”。
  3. 随时说“$project-dev-setup 关闭远程诊断上报”。关闭保存在个人配置，重启和更新不会再打开。关闭后不启动新发送，已发起的一批可能在有界超时内结束。

默认接收方为插件维护者 Clearlovesixteen，地址为 https://project-dev-diagnostics.clearlovesixteen-project-dev.workers.dev/public/events。仅提交白名单元数据，不含源码、PRD/SDD、聊天、命令或真实路径。来源 IP 只用于临时限流，不写入事件或 D1；公开客户端可提交数据，因此不能把公开诊断当成已认证成员或业务质量的证明。

维护者验收

默认接入上线前检查：未授权或越权请求拒绝，白名单字段校验有效，限流返回 429，成功批次确认相同 batch_id 和条数，重复提交不重复入库。再从实际使用环境验证自动收尾与 D1 对应事件。无需前端或自购域名；网络不可用时保留本地队列并退避，不阻断开发。

本机代理与自动发送

0.12.2 的诊断请求优先使用已有 HTTPS_PROXY / HTTP_PROXY（小写优先）和 NO_PROXY；无环境代理时，macOS 只读已有静态 HTTP/HTTPS 代理。回环地址直连，PAC 与仅 SOCKS 的系统代理暂不解析；不修改系统网络或全局 Node 网络。异步 Stop 的单次网络预算为 4 秒，内部进程上限 6 秒，宿主上限 8 秒；同步辅助维持 1.8 秒内部硬期限。升级后按宿主要求核对钩子信任。关闭上传、批次去重、确认后推进游标及失败退避规则保持有效。

维护者怎样分析

node /实际插件/runtime/cli.mjs insights issues --days 7
node /实际插件/runtime/cli.mjs insights trace --id 实际链路摘要 --days 7
node /实际插件/runtime/cli.mjs insights report --days 7 --output /已有目录/新报告.html

本地命令读取当前机器诊断。统计在维护者自己的 D1 账户下查询，不向普通用户开放读接口；ingest_source 可筛选 public 或 private，公开接收标识不认证成员身份。可以在维护者账户通过 Wrangler 执行 SELECT payload FROM events WHERE ingest_source = 'public' ORDER BY occurred_at DESC LIMIT 1000，使用 --json 保存到私有本地文件，再用 insights report --file /私有目录/d1.json --days 7 --output /私有目录/团队诊断.html 生成同口径报告。导入文件上限 1 MB，超限分批；查询 LIMIT 造成的覆盖范围由维护者明确说明，不将导出样本当成全量。修复前后按版本、事件、错误码及同一口径比较，样本不足时明确说明，不推算返工工时或遗漏改善率。

诊断边界

  • 可确认：钩子是否进入、辅助查询是否成功、资料是否输出、回执是否匹配、任务是否绑定、工具是否返回错误、验证器是否真实结束，以及出现问题的版本和链路。
  • 不能直接确认：Codex 是否理解业务、是否真正采用上下文、所有复用和关联修改是否正确。基础事件不含正文，语义问题仍需结合用户明确反馈和实际代码核对。
  • 只统计本插件观察到的事件。钩子未加载、宿主未信任、SDK 在 handler 前拒绝参数、进程被硬杀和绕过插件的操作可能形成缺口。回执不等于使用效果，待复核及保护性拒绝也不必然是插件缺陷。
  • 本地保留 30 天、每日约 1 MiB；接收端按接收时间保留 30 天。安装 ID 是随机标识，项目 / 会话 / 任务是本机 HMAC，仍作为诊断标识保护；不称作不可关联的完全匿名数据。
  • 不采集代码、需求、聊天、查询正文、命令、原始异常或真实路径。关闭本地采集会同步停止远程；历史业务资料不因关闭诊断被删除。
