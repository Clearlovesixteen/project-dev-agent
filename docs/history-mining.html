从项目历史中发现习惯

接入项目时自动整理可用对话，让每次纠正有来源、可核实，也能在下次开发中被找到。

v0.4.0 · 项目结构与业务理解2026.10.14约 4 分钟阅读

这个模块从已有对话寻找你反复强调的开发方式、业务边界和纠正理由，再把相关依据交给后续开发任务。首次接入不要求手写一份习惯清单；从当前 Codex 会话调用 project-dev Skill 即可开始。

怎样使用

$project-dev 帮我实现这个需求：……

Skill 在新会话中先检查项目状态。有未完成批次就续接；否则扫描当前历史快照。它读取每个文本批次、保存分析结果，然后继续需求。仅想先整理习惯，可说 $project-dev 分析当前项目的历史习惯，给我查看报告。分析使用当前会话的模型和额度，无需额外 API Key；首次历史较多时耗时与额度也会增加。

中断后可以继续，不必从头读。工具使用日志指纹跳过未变化的解析，使用批次内容摘要复用已有分析。新增消息会在下次扫描发现，改变的末尾批次需要重新分析。不会持续后台监听；日常任务通过 Skill 触发。

“项目全部历史”的实际范围

读取本机 CODEX_HOME 或 ~/.codex 下的 sessions、archived_sessions。依靠会话元数据中的仓库路径归属，并检查每轮工作目录。仅在其他对话里提到项目名称，不会被归入本项目。

  • 包含用户消息与助手可见回复；长消息分段保留，不只抽样开头。
  • 内部子代理、审查记录、工具输出、模型推理、系统环境注入和压缩摘要被排除。
  • 附件消息会计数，但图片、PDF 等附件正文不会由这个文本适配器自动解析。
  • 云端未同步、已删除的历史及迁移前其他路径的会话不会自动找回；当前不支持 Claude、飞书或其他聊天平台。
  • 无法归属、格式损坏或超过读取上限时报告不完整，不能把扫描成功说成全部分析完成。

怎样判断一条“习惯”

每条候选包含规则、适用路径和条件、个人或项目范围、判断理由、用户原话、时间与待核实问题。助手自己提出的方案不能冒充用户习惯；一次性改需求、回退或授权，也不能泛化成永久约定。

语义判断由当前 Codex 完成。MCP 能验证引用确实来自本批用户消息，不能自动证明推断本身正确；仍要结合当前代码核实。重复规则合并依据，同主题不同说法保留为潜在冲突。检索旧关键词时也返回后续版本，按时间给出上下文；不能只凭“较新”就自动判定生效。

knowledge_search 的 history.hints 最多返回 5 条相关候选及同主题摘要，每条保持 status: candidate、effective: false。确认过的共享知识保持原有检索和版本机制；历史候选不写入任务的已确认知识版本。

模块与调用链

部分职责
codex-reader.ts流式解析 JSONL，识别项目、会话与消息，排除元数据，分段和常见凭据脱敏
service.ts扫描快照、内容分批、增量缓存、待分析队列与引用校验
store.ts文件锁、批次进度、候选合并、时间与潜在冲突
search.ts按路径与分词匹配检索，携带同主题的后续纠正
report.ts生成本地 HTML，转义历史文本，按条数与字节数分页展示全部候选
Skill驱动扫描 → 下一批 → 语义分析 → 保存循环，再将相关候选和当前代码一起核实

新增 3 个 MCP 工具：history_scan、history_next、history_record。每次都显式传当前仓库的绝对路径 project，由既有 workspace 机制检查范围和隔离状态。扫描只建立文本队列；直到所有批次有分析记录才显示已分析。

命令行也提供 history scan/next/record，适合检查或接入脚本；单独执行 scan 不会自动调用模型。输入契约见 Skill 内置的历史输入参考。底层设有有界读取：最多 20,000 个目录条目、8 层目录、每行 8 MB、单会话 1,200 万可见字符、每次快照 1,000 个批次；超限会明确提示缺失，生成的单个本地文件上限为 64 KiB。

数据存放与团队共享

.project-dev/local/history/
  manifest.json       扫描快照与覆盖统计
  batches/*.json      待分析的可见文本及来源
  analysis/*.json     已分析批次、候选和原话依据
  cache/*.json        原始日志指纹与批次索引
  report.html         报告入口
  report-*.html       候选较多时的后续页面

原始日志只读。以上内容保存在 Git 忽略的本地目录，不随工具包或业务代码自动共享。常见凭据会尝试脱敏，这不是完整的隐私识别器。提交团队知识前仍需检查摘录内容与适用范围。

候选可通过 history propose --project /absolute/project --id habit-… 导入既有知识草稿审查流程。明确核实来源、解决冲突、得到用户审查后，才通过 knowledge review 确认为共享规则。HTML 用于阅读说明与报告；Skill 和机器知识协议保留要求的文件格式。

这一版能验证到哪里

自动化检查覆盖项目归属、归档记录、用户原话校验、增量续接、未完成来源、HTML 转义与分页、跨进程 MCP、旧版 Skill 安全升级。详见 验证记录。没有做 AST 影响分析、向量检索或跨项目知识合并；对实际减少纠偏与漏改的效果，仍需要真实需求试用。
