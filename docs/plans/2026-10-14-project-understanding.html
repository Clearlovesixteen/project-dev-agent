首次扫描与逐步业务建模

2026-10-14 · 用户已确认实施 · 目标版本 v0.4

设计决定

首次接入建立覆盖仓库的结构索引；业务理解围绕具体需求积累。沿用本地 MCP 与 Codex Skill，不另建模型服务。原始业务文件只读，状态留在 Git 忽略目录。

结构索引记录模块、角色线索、直接导入、依赖声明及来源哈希。文件归类和导入解析属于导航线索，不能证明业务关联完整。业务候选记录术语、流程、职责、相关路径、原文依据与疑问；不自动升级为团队规则。

实施顺序

  1. 实现有界全仓枚举与结构提取，排除依赖、生成文件、敏感配置和嵌套仓库，报告覆盖范围。
  2. 增加项目上下文查询：检索文件、直接依赖与使用方，核对选中来源的新鲜度。
  3. 增加模块理解记录：校验源码引用与版本，保留修订，来源变化时显示待复核。
  4. 接入首次使用 Skill、知识检索和 CLI，提供 HTML 项目报告。
  5. 验证异常与跨仓库隔离、回归测试、打包安装，在 WMS 验证结构与一个业务模块，保留原有改动。

取舍与验收

选择轻量结构扫描与按需理解，降低首次语义分析成本。暂不提供完整 AST、运行时调用图或自动全业务建模。扫描会读取本地文件计算版本，重复扫描复用未变化文件的提取结果；后续查询核对相关源码，但不宣称发现所有新增文件或业务影响。

验收要求：首次可扫描、后续可检索，候选有可验证原文，变更后有失效提示，中断不会发布半份索引，报告可浏览全部结构记录，安装升级不覆盖自定义 Skill。团队收益需继续用真实需求观察。
