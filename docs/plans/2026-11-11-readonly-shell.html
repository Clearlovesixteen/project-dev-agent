只读终端误拦截修复

目标：有其他会话活跃任务时，正常读取源码不进入写入准备和任务归属检查。实际修改、含写入的组合命令及无法确认的复杂脚本继续受控。

范围与架构

词法解析、命令能力判定、宿主工具适配、诊断分别维护。使用有容量和递归上限的纯 TypeScript 解析，不执行待分析命令、不启动额外解释器、不引入运行时服务。按 shell 规则区分引号内普通参数、真正管道、重定向和动态表达式；保留插件管理与工作区切换的既有授权通道。

  1. tests/shell-readonly.test.ts：先用旧版实现验证引号正则、Windows 命令、只读组合及真实写入的红绿结果。
  2. src/hooks/shell-syntax.ts：有界词法解析，识别 Posix、PowerShell、cmd 的静态词、引号、转义、操作符和动态语法。
  3. src/hooks/shell-commands.ts 与 shell-policy.ts：程序名规范化、读取/写入/未知/管理分类；只放行可确定的读取链路，剥离支持的 shell 包装，不将整个 PowerShell 脚本视为只读。
  4. tool-policy.ts、handler.ts、write-gate.ts：读取先分流；真实修改保留项目上下文、任务和目标检查。未知命令拒绝时明确说明无法确认只读。
  5. 使用既有 decision.recorded 与固定原因码记录分类，无命令、路径或正文；诊断故障不阻断正常读取，不改变远程采集白名单。
  6. tests/readonly-hooks.integration.test.ts：真实打包 MCP 与钩子，构造两个会话共享分支；读取允许，修改拒绝，原任务及业务文件保持。Windows 原生 PowerShell 执行读取管道，补充 Windows CI。
  7. 完整回归、三个 Node 版本与 Windows 检查全部通过后发布 0.13.5，再更新本机并独立核验安装版本、运行版本和宿主钩子信任。

验收边界

不通过删除任务、接管会话或停用钩子解决误判；不宣称静态分类能推导任意解释器脚本。旧 manual 自动迁移策略、项目范围和诊断开关沿用 0.13.4。另一个 Windows 缓存备份权限错误不混同为本缺陷。
