第一次开发时完成初始化

用户安装插件后，在业务仓库直接使用“项目开发”描述需求。插件检测当前项目，首次使用完成初始化，后续复用配置。“项目设置”只用于查看配置或调整工作目录。

实现方式

  1. Skill 从当前任务确定 Git 根目录，传给现有的 project_prepare。MCP 在插件缓存中启动，不能用进程工作目录猜测业务仓库。
  2. 已有配置时，按原工作范围校验仓库并准备项目。未配置时，先检查绝对路径、Git 根目录、提交基线、Git 元数据位置和本地状态路径。
  3. 开发调用使用 apply: true，在原配置锁及修订检查下保存当前仓库，再补齐 Git 本地忽略规则。并发选择不会相互覆盖。
  4. 初始化完成后，Skill 继续结构扫描、项目历史整理和原需求；相关业务理解按实际需求逐步建立。

把首次初始化纳入 MCP 的现有准备工具，可以验证真实状态，并与后续准备共用同一入口。安装时不再启动单独的配置引导，也不增加新的必填命令。

不同场景的行为

场景行为
首次开发初始化当前仓库，默认范围仅为该仓库。
仅查看状态预览初始化信息，不保存配置、不修改忽略规则。
已有配置或升级复用原配置，保留任务、历史候选和报告。
已有未提交代码保留现有代码，可初始化及扫描；正式建立任务仍按原基线要求处理。
其他目录或 Git 元数据在范围外说明问题，由用户选择工作范围，不自动扩大到父目录。
配置损坏或有其他写入者返回明确错误并保留原配置，核对状态后再重试。
