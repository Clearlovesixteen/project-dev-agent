自动辅助与诊断可靠性修复

目标：自动辅助只处理允许范围内的开发；真正失败可定位；诊断积压能够在现有时间预算内逐批发送。技术：TypeScript、Node.js、原生 Codex 钩子、已有 JSONL 队列及 Cloudflare 接收端。

保留手动模式、已有关闭选择、工作目录边界、业务资料和既有验收门槛。不改变网络出口或 TLS 校验，不把受保护拒绝当作程序崩溃，不把缺少同事上报直接解释为同事没有使用。
步骤修改与验证
1. 固定复现新增 tests/diagnostic-reliability.test.ts，先验证非项目/范围外钩子、首次接入、原因码、积压队列和报告截断提示在旧实现中失败；使用隔离配置与回环接收服务。
2. 自动入口修改 src/hooks/handler.ts，提取 hooks/project.ts：区分非 Git、范围外、未配置和真实失败。未配置的 auto 开发请求只提供 project_prepare 入口，由已授权工作流完成初始化；钩子不擅自变更工作范围。
3. 有界队列提取 observability/upload-queue.ts，修改 uploader.ts：最多 4 批、每批 50 条，共享原有发送时间预算。每批确认即保存游标，后批失败保留先前进度；停止/配置变更后不继续发新批。
4. 诊断解释writer.ts 的语义事件沿用主调用原因码。insights.ts 区分工具主调用与派生事件，兼容历史 incomplete / OK；明确事件全量与链路展示上限。只记录安全的固定错误码，不上传错误正文。
5. 回归与交付旧配置、未授权路径、坏配置、ACK 丢失、后批失败、关闭、时间上限等回归；运行类型检查、全量测试、最低 Node 兼容、真实插件入口与原生宿主连接。同步 README、诊断说明、发布产物与版本，保留私人演讲素材。

复现命令：node node_modules/typescript/bin/tsc -p tsconfig.json，随后 node --test dist/tests/diagnostic-reliability.test.js。修复后用同一命令复测，进一步运行 npm run check 和最低版本运行检查。

验收：非项目正常跳过，首次 auto 入口可达，未扩大范围；积压分批减少且持久确认有效，部分成功后不回滚；报告说明不完整覆盖，不用异常事件数冒充独立故障或团队使用效果。线上历史原始数据保留，新事件不能倒推旧错误根因。
