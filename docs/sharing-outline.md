# 实践分享提纲

建议 20–30 分钟，主题：让 Codex 复用项目经验并核对关联改动。

1. 真实痛点：反复解释代码习惯、业务约束，以及点对点修改造成的漏改。
2. 演示：查询知识、建立关联清单，展示“只改写入后仍有待核对项”，解释旧测试通过为何可能不足。
3. 经验复用：一次纠正如何形成候选草稿；同事审查哪些问题；确认后下一任务怎样使用。
4. 接入方式：项目 Skill、本地 MCP、Git 管理知识；同事如何初始化项目和开始任务。
5. 试用结果：真实对照案例、纠偏和误报数据、额外耗时。当前待实测，自动化测试数量不能代替。
6. 边界与改进：维护成本、整文件哈希的复核噪声、未记录的业务关联、后续检索和影响分析。

实际分享后留存日期、参与范围、演示材料和反馈，作为季度内容分享证据。当前只是提纲，尚未开展分享。
